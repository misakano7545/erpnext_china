# 资产负债表 / 损益表 设置 用户操作手册

适用模块：ERPNext China（中国会计准则报表增强）
涉及单据：

- `Balance Sheet Settings`（资产负债表设置，单例 `issingle`）
- `Profit and Loss Statement Settings`（损益表设置，单例 `issingle`）

> 这两个单据都是**单例类型**，每个站点只有一份设置（不会新增多条）。所谓"创建设置 / 导入设置"，就是把这一份设置填写/导入正确并保存。

---

## 1. 为什么要设置

ERPNext 原生的资产负债表、损益表是按系统固定结构生成的。中国报表（小企业会计准则 / 企业会计制度）对行项目、科目归集方式有特定要求。`erpnext_china` 通过这两张"设置单"让你**自定义每一行取哪些科目、如何汇总**，从而适配本企业实际的科目表。

报表渲染时只认这里配置的行与科目号；科目表里有但没被任何行引用的科目，不会体现在报表中。

---

## 2. 核心概念（务必先读懂）

### 2.1 两种计算方式（calc_type）

每一行有两种取值方式，由"计算方式"字段决定：

| 计算方式 | 含义 | 计算来源填什么 |
| --- | --- | --- |
| `Closing Balance`（期末余额） | 取若干科目的期末余额相加 | **科目编号**，多个用英文逗号 `,` 分隔 |
| `Calculate Rows`（计算行） | 取其他行的计算结果做加减 | **其他行的行号 idx**，多个用英文逗号 `,` 分隔 |

### 2.2 计算来源（calc_sources）语法

- **科目号模式**（计算方式=期末余额）：`1001,100201,100202`
  - 科目号前可加 `-` 表示**减去**该科目（用于抵减类科目，如累计折旧 `-1602`、累计摊销）。
  - 多个科目并列表示相加；加 `-` 前缀表示相减。
- **行号模式**（计算方式=计算行）：`2,3,4,15,30`
  - 行号即表格每行的 `idx`（最左序号列）。
  - 行号前可加 `-` 表示减去该行（如损益表 `营业利润 = 1,-2,-3,-11,-14,-18,20`）。

### 2.3 显示相关字段

| 字段 | 说明 |
| --- | --- |
| 名称 / label | 报表上显示的文字 |
| 缩进 indent | 0=顶层标题，1=子项，2=更细子项（仅影响显示层级，不影响计算） |
| 粗体 bold | 是否加粗（一般"合计"行用） |
| 空白 empty | 勾选后该行不显示名称（用于占位/留白，或仅单侧有内容的行） |

### 2.4 资产负债表独有的三个"合计行"字段

资产负债表设置单顶部有三个整数字段，必须指向对应"合计"行的 **idx**：

- `资产合计行 asset_row`
- `负债合计行 liability_row`
- `权益合计行 equity_row`

范例中分别为 `31 / 22 / 30`。改了行结构后务必同步更新这三个值，否则报表合计取数错位。

损益表没有这三个字段（它的合计由"计算行"自动算出）。

## 3. 手动设置操作流程

1. **进入单据**：搜索 / 模块菜单进入 `Balance Sheet Settings` 或 `Profit and Loss Statement Settings`。
2. **导入范例数据**（首次为空时界面有按钮）：点击「导入范例数据」，系统把 `example_data.json` 的样板填进来，作为可改的基底。
3. **逐行替换科目号**：在表格里把每行的"计算来源"从样板科目号改成**本企业科目表的实际科目编号**。行结构、行名、缩进、计算方式一般都保持不变，只改科目号。
4. **设置三个合计行**（仅资产负债表）：确认 `资产合计行 / 负债合计行 / 权益合计行` 指向正确的 idx。
5. **保存**。
6. **校验完整性**：点击「Check Missing Accounts」按钮，打开 `BS and PL Missing Account` 报表。它会列出**科目表里存在、但未被本设置任何行引用**的科目，据此补遗漏或确认是有意排除。

## 4. AI 智能生成配置（推荐，省时且不易错）

企业中明细科目很多时，手动逐行改科目号很繁琐。可用大模型一次性生成适配的 JSON，再用 ERPNext 标准功能一键建单。

### 4.1 原理（重要，请读清楚）

> **直接 `Ctrl+V` 粘贴一个包含 `doctype` 的 JSON，是 ERPNext 的标准功能**：在 ERPNext 的任意界面（桌面、列表、表单都行）粘贴这样的 JSON，系统会自动**创建并打开已填好内容的对应单据表单**，你检查确认后点"保存"即可。

本设置单也完全支持这个标准功能。所以 AI 协助生成的整个流程是：

**上传一份"设置单模板 JSON" + 上传一份"目标科目表" → 大模型参考模板结构、按你的科目表重新生成一份新的"配置单 JSON" → 你复制这段 JSON 文本 → 在 ERPNext 任一界面直接 `Ctrl+V` → 系统自动打开已填好内容的"资产负债表设置 / 损益表设置"表单 → 你检查确认 → 点保存。**

（粘贴 JSON 直接建单是 ERPNext 原生标准能力，无需额外开发；本应用额外还提供了一个「从剪贴板粘贴 JSON」按钮，作为"在当前已打开的表单内替换内容"的显式入口。）

### 4.2 操作步骤

1. **取得模板 JSON（任选其一）**
   - 进入设置单 → 点「导入范例数据」→ 用浏览器开发者工具 / API 导出当前单据 JSON；
   - 或直接使用系统自带的 `example_data.json`（资产负债表 / 损益表各一份）；
   - 或以本企业现有的一份已配置好的设置单 JSON 作模板。
2. **准备目标科目表**：列出科目编号、科目名、层级（父科目 / 缩进级次）。
3. **交给大模型**：把"模板 JSON"和"目标科目表"填入标准化提示词（见配套文档 `报表设置-AI提示词模板.md`）发给任意支持长文本的 AI。
4. **复制 AI 返回的纯 JSON**：顶部必须含 `"doctype": "Balance Sheet Settings"`（或 `Profit and Loss Statement Settings`）。
5. **在 ERPNext 任意界面直接 `Ctrl+V` 粘贴**：系统自动打开已填好内容的设置表单（这就是标准建单功能）。
6. **检查三个合计行与关键合计**，点「Check Missing Accounts」核对遗漏，**保存**。

### 4.3 模板 JSON 怎么拿 / 目标科目表怎么整理

见配套文档 `报表设置-AI提示词模板.md`（含标准提示词与科目表格式）。

## 5. 组科目（父科目）自动汇总余额（务必了解）

**结论：在"计算来源"里写一个组科目（父科目）的编号，系统会自动把它下面所有记账（叶子）科目的余额都算进去。** 所以你不必把每个叶子科目都列出来，用父科目号即可一次性覆盖整组。

代码依据：

- **损益表**：`get_acc_nums` 显式把组科目展开为其下全部非组（记账）科目：
  ```98:106:apps/erpnext_china/erpnext_china/erpnext_china/report/fin_profit_and_loss_statement/fin_profit_and_loss_statement.py
    if account and account.is_group:
      child_account_nums = [acc.account_number for acc in accounts
         if acc.is_group == 0 and acc.lft > account.lft and acc.rgt < account.rgt]
      parent_children_map[acc_num] = child_account_nums
  ```
- **资产负债表**：取数用的是 `get_balance_on`，对组科目会用子树 `exists` 子查询把整组余额聚合（这是 ERPNext 标准逻辑）：
  ```249:255:apps/erpnext/erpnext/accounts/utils.py
  		if acc.is_group:
  			cond.append(
  				f"""exists (
  				select name from `tabAccount` ac where ac.name = gle.account
  				and ac.lft >= {acc.lft} and ac.rgt <= {acc.rgt}
  			)"""
  			)
  ```

**好处**：让 AI 映射科目时，可以用"父科目编号"代替一长串叶子编号，既简洁又不会漏。

**注意**：若同一个下级科目既被"父科目"包进去、又在别处单独列出，会触发**重复科目橙色警告**（不影响保存，但会导致该科目余额被重复计算）。组科目和它自己的某个叶子不要同时出现在不同行。

## 6. 资产负债表不平怎么办（表头"利润/(亏损)(贷方)"不为 0）

运行资产负债表后，报表**表头**会显示一行 **`Provisional Profit / Loss（利润/亏损，贷方）`**，它的值等于：

```
利润(亏损) = 资产合计 − 负债合计 − 权益合计
```

**正常情况下（已期末结账、配置正确），这个值应为 0。** 如果它**不为 0**，说明资产负债表还"不平"，最常见原因有四类：

1. **配置错误**：行结构、计算方式、计算来源写错（比如把科目号写成了行号，或行号引用错）。
2. **漏了有金额的科目**：某些科目在科目表里有余额，却没被任何报表行引用 → 这部分金额"消失"在表外。用「Check Missing Accounts」可一次性列出所有未被引用的科目。
3. **科目重复放在不同报表行**：同一科目在多处被加总，导致合计虚高 / 虚低（系统会弹橙色 "Account X already in Row Y" 警告）。
4. **期末结账（结转损益）还没做**：损益类科目余额尚未结平到"本年利润"，这个未结转的净利润正好等于上面的差额。

**排查顺序建议**：
- 先点「Check Missing Accounts」核对是否有遗漏科目；
- 再检查是否漏做"结转损益"凭证；
- 最后逐行核对计算方式与计算来源、合计行 idx 是否指向正确。

## 7. 未结账时把损益科目放进"未分配利润"行的限制与符号陷阱

有人会想：既然没做期末结账（损益没结到本年利润），能不能直接把损益科目写到资产负债表"未分配利润"那一行，让报表把净利润体现在权益里？

**技术可行性分两种报表模式：**

- **两栏式资产负债表**：取数时加载**全部**科目（含 Income / Expense），所以"未分配利润"行写损益科目号能被找到并取数。
  ```202:203:apps/erpnext_china/erpnext_china/erpnext_china/report/fin_balance_sheet/fin_balance_sheet.py
      accounts = get_accounts_data(self.company)
  ```
- **单栏式资产负债表**：取数时按 `root_types=['Asset','Liability','Equity']` **过滤掉了损益类科目**，损益科目号不在取数范围内，写进去会取到 **0**，等于无效。
  ```402:402:apps/erpnext_china/erpnext_china/erpnext_china/report/fin_balance_sheet/fin_balance_sheet.py
      accounts = get_accounts_data(self.company, root_types=['Asset', 'Liability', 'Equity'])
  ```

**符号陷阱（即使两栏式能用，也很危险）：**
权益侧（右栏）对非资产科目做了反向处理 `closing_balance = 0 − closing_balance`
```219:222:apps/erpnext_china/erpnext_china/erpnext_china/report/fin_balance_sheet/fin_balance_sheet.py
      else:
        d.opening_balance = ...
        d.closing_balance = 0 - closing_balance
```
收入（贷方余额）、费用（借方余额）在权益侧都会变成**负值**。要把"净利润"正确表示为正的权益，需要非常小心地配正负号，极易算错。

**结论与建议：**
- **推荐做法**：正常做"结转损益（Period Closing Voucher）"，让本年净利润落到 `本年利润(3103)`，再结合 `利润分配(3104)`——也就是范例数据里"未分配利润"行 `calc_sources = "3103,3104"` 的本来写法，无需任何改动即可正确反映。
- **变通做法（仅两栏式、不推荐）**：直接把损益科目写进"未分配利润"行。可行，但符号易错，且会把"未结账"的预警掩盖掉（见第 6 节，差额被强行填平，表头利润/亏损变成 0，反而发现不了漏结账）。

## 8. 注意事项

1. **导入/粘贴后必须点"保存"**：`Ctrl+V` 或按钮只是把内容填进表单，未落库。
2. **改了行结构要同步改三个合计行**：资产负债表顶部的 `asset_row/liability_row/equity_row` 是写死的 idx。
3. **科目号必须存在于本企业科目表**：引用了不存在的科目不会报错，但该行该部分取数为 0（易被忽略）。
4. **单例限制**：全站只有一份，覆盖式保存，导入前确认是否要备份旧设置。
5. **`Ctrl+V` 粘贴 JSON 建单是 ERPNext 标准功能**，无需额外开发；若你改过本单据的前端脚本，生产环境需 `bench build` 并清除浏览器/服务端缓存后再生效。

## 9. 常见错误与排查

| 现象 | 原因 | 排查/解决 |
| --- | --- | --- |
| 表头"利润/(亏损)(贷方)"不为 0 | 配置错 / 漏科目 / 科目重复 / 未结账（第 6 节四类） | Check Missing Accounts + 确认是否结转损益 |
| 保存时报错 "Referenced row X does not exist" | 某"计算行"引用了不存在的行号 | 检查 `calc_sources` 里的行号是否超出当前总行数 |
| 保存时报错 "... is not a valid row number" | 计算来源里混入了非数字 | 计算来源只能含数字和逗号 |
| 报表总额偏大 / 翻倍 | 同一科目被多个行重复引用（仅橙色警告） | Check Missing Accounts 核对；去重 |
| 资产 ≠ 负债+权益 | 三个合计行 idx 指错，或合计行漏算某些行 | 核对 `asset_row/liability_row/equity_row` 与合计行 idx |
| 固定资产虚高 | 累计折旧等抵减科目忘了加 `-` | 在资产类抵减行源加 `-1602` 之类前缀 |
| 营业利润/净利润算错 | 加减号写反（成本费用应为 `-`） | 损益表用 `1,-2,-3,…`；被减项行号前必须带 `-` |
| 报表缺了一整块科目 | 这些科目没被任何行引用 | Check Missing Accounts 列出遗漏科目，补到对应行 |
| 单栏式资产负债表里"未分配利润"行用损益科目却为 0 | 单栏式过滤掉了损益类科目 | 改用两栏式，或先做结转损益让净利润进本年利润 |
| 组科目和它某个叶子同时出现在不同行 | 重复计算 | 组科目已含全部下级，不要再单独列其叶子 |
| 粘贴 JSON 没反应 | JSON 顶部 `doctype` 缺失或不匹配 | 确认 JSON 含 `"doctype": "Balance Sheet Settings"`（或 P&L），在 ERPNext 任意界面 `Ctrl+V` 即可 |

## 10. 字段速查表

**资产负债表行（Balance Sheet Settings Item）**：`lft_empty/lft_bold/lft_name/lft_indent/lft_calc_type/lft_calc_sources`（左=资产），`rgt_*` 同样一组（右=负债与权益）。

**损益表行（Profit and Loss Statement Settings Item）**：`label / indent / calc_type / calc_sources / amount_from`。

`calc_type` 取值：空（仅标题）、`Closing Balance`、`Calculate Rows`。
`calc_sources`：科目号或行号，逗号分隔，可加 `-` 取负。
