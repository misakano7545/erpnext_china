# 报表设置 · AI 提示词模板（标准化）

用途：让 AI 参考一份**现成的报表设置 JSON（模板）**，结合**目标企业的科目表**，自动生成一套适配该科目表的、可直接粘贴导入的设置 JSON。

配套文档：`资产负债表与损益表设置-用户操作手册.md`

---

## 一、核心原理（先读懂，避免走弯路）

**直接 `Ctrl+V` 粘贴一个含 `doctype` 的 JSON，是 ERPNext 的标准功能**：在 ERPNext 任意界面（桌面、列表、表单均可）粘贴这样的 JSON，系统会**自动创建并打开已填好内容的对应单据表单**，检查确认后点"保存"即可。本设置单（资产负债表设置 / 损益表设置）完全支持。

所以这里的工作流就是：
1. 给大模型一份"设置单模板 JSON"（结构基准）；
2. 给大模型一份"目标科目表"（编号+名称+层级）；
3. 大模型参考模板结构、按目标科目表重新映射科目号，输出**新的配置单 JSON**；
4. 你复制这段 JSON；
5. 在 ERPNext 任一界面 `Ctrl+V` → 自动打开已填好的设置表单 → 检查 → 保存。

（本应用额外提供了一个「从剪贴板粘贴 JSON」按钮，作为"在当前已打开的表单内替换内容"的显式入口；但标准做法就是直接 `Ctrl+V`。）

---

## 二、使用步骤

1. **取得模板 JSON**（任选其一）
   - 进入设置单 → 点「导入范例数据」→ 用浏览器开发者工具 / API 导出当前单据 JSON；
   - 或直接使用系统自带的 `example_data.json`（资产负债表 / 损益表各一份）；
   - 或以本企业现有的一份已配置好的设置单 JSON 作模板。
2. **准备目标科目表**：列出科目编号、科目名、层级（父科目 / 缩进级次）。
3. **交给大模型**：把下面「标准提示词」中的 `{粘贴模板JSON}` 与 `{粘贴目标科目表}` 替换为真实内容，发送给任意支持长文本的 AI。
4. **复制 AI 返回的纯 JSON**（顶部须含 `"doctype"`，字段名用英文，值沿用模板字段）。不要 markdown 代码块围栏也可以，系统会自动解析。
5. **在 ERPNext 任意界面直接 `Ctrl+V` 粘贴**：系统自动打开已填好内容的"资产负债表设置 / 损益表设置"表单。
6. **检查三个合计行（仅资产负债表）与关键合计**，点「Check Missing Accounts」核对遗漏，**保存**。

## 三、标准提示词（复制即用）

> 复制下面整段，替换两处花括号占位符即可。

```
你是一名熟悉中国会计准则 ERPNext（erpnext_china）报表配置的财务系统顾问。

我要为【{报表类型：资产负债表 / 损益表}】生成一份"报表设置"JSON，用于直接粘贴导入系统（ERPNext 标准功能：任意界面 Ctrl+V 含 doctype 的 JSON 即自动建单）。
系统已有的设置单数据结构（模板）如下，请你严格沿用它的"行结构、行名、缩进、计算方式、行号(idx)"，只把【计算来源】里的科目编号替换成目标科目表中对应的实际科目编号：

### 模板 JSON（现成设置，结构基准，不要改动行名/行号/缩进/计算方式）
{粘贴模板JSON}

### 目标科目表（本企业实际科目，含编号/名称/层级）
{粘贴目标科目表}
（格式示例：
1001 库存现金
1002 银行存款
  100201 活期存款
  100202 定期存款
1601 固定资产
1602 累计折旧
...
也可提供父级+子级的层级文本，或"科目编号,科目名称,级次"的表格）

### 任务与硬性规则
1. 保持模板的每一行的 idx、名称、indent(缩进)、bold(粗体)、empty(空白)、calc_type(计算方式) 完全不变；损益表保持 label 不变。
2. 对于 calc_type = "Closing Balance"（期末余额）的行：把 calc_sources 里的科目编号，替换成目标科目表中"会计含义相同"的科目编号。
   - 优先用最贴近的叶子科目；若目标科目表用"父科目汇总下级"，可用父科目编号替代多个子科目（组科目会自动汇总其下所有科目余额）。
   - 模板中带 "-" 前缀的抵减类科目（如累计折旧 -1602、累计摊销、各类减值准备），在目标科目表中也要找到对应抵减科目并保留 "-" 前缀。
3. 对于 calc_type = "Calculate Rows"（计算行）的行：calc_sources 是"其他行号"，【禁止改动行号】，只做必要的 +/- 符号核对（被减项带 -）。
4. 若模板中某个会计概念在目标科目表里【找不到对应科目】：
   - 该行仍保留，但 calc_sources 置为空字符串 ""（不要编造不存在的科目号）；
   - 并在 JSON 之外用一段"说明"列出这些未映射的概念，便于人工补录。
5. 确保 calc_sources 中出现的每一个科目编号都真实存在于上面的目标科目表。
6. 资产负债表请保留并核对顶部三个字段：asset_row（资产合计行）、liability_row（负债合计行）、equity_row（权益合计行），其数值必须等于对应"合计"行的 idx（沿用模板即可，除非你增删了行）。
7. 只输出一个完整、可被系统直接解析的 JSON 对象，不要包含任何解释文字、不要使用 markdown 代码块围栏（除非用 ```json 包裹且内部为纯 JSON）。

### 输出 JSON 结构规范（必须严格匹配，字段名用英文，值用模板里的字段）
资产负债表输出示例：
{
  "doctype": "Balance Sheet Settings",
  "asset_row": 31,
  "liability_row": 22,
  "equity_row": 30,
  "items": [
    {
      "idx": 1,
      "lft_empty": 0, "lft_bold": 1, "lft_name": "流动资产：", "lft_indent": 0, "lft_calc_type": "", "lft_calc_sources": "",
      "rgt_empty": 0, "rgt_bold": 1, "rgt_name": "流动负债：", "rgt_indent": 0, "rgt_calc_type": "", "rgt_calc_sources": ""
    }
  ]
}
损益表输出示例：
{
  "doctype": "Profit and Loss Statement Settings",
  "items": [
    {"idx": 1, "label": "一、业务收入", "indent": 0, "calc_type": "Closing Balance", "calc_sources": "5001,5051"}
  ]
}
（items 内字段：资产负债表用 lft_*/rgt_* 各一组；损益表用 label/indent/calc_type/calc_sources，amount_from 默认 Balance 可省略）

请现在基于我提供的模板与目标科目表，输出最终 JSON。
```

## 四、给 AI 的科目表怎么整理（越清晰越好）

推荐提供"编号 + 名称 + 层级"三要素，二选一：

**A. 缩进文本（直观）**
```
1001 库存现金
1002 银行存款
  100201 人民币户
  100202 外币户
1122 应收账款
1601 固定资产
1602 累计折旧
...
```

**B. 表格/CSV（适合大量科目）**
```
科目编号,科目名称,级次,父科目编号
1001,库存现金,1,
1002,银行存款,1,
100201,人民币户,2,1002
1601,固定资产,1,
1602,累计折旧,1,
```

层级信息帮助 AI 判断"用父科目聚合还是用多个子科目"，以及识别抵减类（累计折旧、减值准备）科目。

---

## 五、导入后必做检查

1. `Ctrl+V` / 按钮导入后**点保存**。
2. 点「Check Missing Accounts」：查看是否有科目表存在但未被引用的科目，按需补录。
3. 资产负债表核对顶部三个合计行 idx 是否指向正确的"合计"行。
4. 跑一遍实际报表，确认 资产 = 负债 + 权益、损益勾稽关系成立；表头"利润/(亏损)(贷方)"应为 0（不为 0 见手册第 6 节排查）。

---

## 六、常见问题（针对 AI 生成）

- **AI 编造了不存在的科目号**：严格按规则 4/5，缺失概念留空并列出；导入后「Check Missing Accounts」也会暴露。
- **抵减科目没加 `-`**：在提示词中已强调，生成后人工扫一眼含"减：""累计折旧""摊销""减值"的行。
- **行号错乱**：AI 不应改动 Calculate Rows 的行号；若其自行增删行，需同步修正三个合计行与所有行号引用。
- **粘贴没反应 / 未自动建单**：确认 JSON 顶部 `"doctype"` 与单据一致（资产负债表=`Balance Sheet Settings`，损益表=`Profit and Loss Statement Settings`），然后在 ERPNext 任意界面 `Ctrl+V` 即可（这是标准功能，无需打开特定表单）。
