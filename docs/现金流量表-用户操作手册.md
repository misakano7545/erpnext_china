# 现金流量表 用户操作手册

适用模块：ERPNext China（中国财务报表）
涉及单据：

- `现金流量表`（Cash Flow）：按月 **可提交** 单据，命名规则为 `公司_会计年度_月`
- `现金流编码`（Cash Flow Code）：定义报表每一行的取数规则，app 安装后自动加载（系统已带范例），属**事先维护**的基础数据
- `现金流量表分录`（Cash Flow Item）：子表，由系统从总账自动拉取，逐笔指定编码
- `现金流量表小计`（Cash Flow Subtotal）：子表，**只读**，保存时由系统自动计算

> 与资产负债表/损益表"设置单"不同，现金流量表是**逐月一张业务单据**：先拉取当月所有现金/银行科目的总账分录（即总账凭证里的每行借贷），再人工（或自动）把每一笔分录归到某个现金流编码，保存后系统自动汇总出"本月金额 / 本年累计金额"，最后**提交**才算定稿（且只有已提交的上一月，才会被下一月的"本年累计"接上）。

---

## 1. 为什么要做这张表

ERPNext 原生的现金流量表按系统固定模板生成，对"每一笔现金收支归到哪一类"（经营 / 投资 / 筹资）缺乏中国报表要求的灵活归集。`erpnext_china` 改成**单据驱动**的方式：

- 你先维护一套现金流编码（项目编码与归类规则），相当于报表的"行模板"；
- 每月新建一张现金流量表单据，系统把当月所有现金（Cash）/ 银行（Bank）科目下的总账分录拉进来；
- 你给每一笔分录指定一个现金流编码（也可让系统按科目/往来单位自动推定）；
- 保存时系统按现金流编码的"公式"自动算出小计、净额、期初/期末余额，形成正式现金流量表。

报表只认被现金流量表分录引用的分录；未指定编码的分录会留在明细里、但不参与任何汇总（需人工补码）。

## 2. 核心概念（务必先读懂）

### 2.1 四个角色的关系

| 单据 / 子表 | 角色 | 谁来填 |
| --- | --- | --- |
| 现金流编码 | 报表**行模板**：定义每个项目编码的名字、归类、公式、是否流出 | 一次性维护（安装即带范例） |
| 现金流量表 | 某公司、某会计年度、**某月**的一张表 | 每月新建 |
| 现金流量表分录 | 当月一笔现金/银行总账分录 + 它归属的编码 | 系统拉取，人工补码 |
| 现金流量表小计 | 保存后自动生成的汇总行（本月金额 / 本年累计金额） | 系统算，只读 |

### 2.2 公式（formula）—— 决定这一行怎么算

现金流编码的"公式"字段有四种取值：

| 公式取值 | 含义 | 取什么数 |
| --- | --- | --- |
| 空（不填） | **明细项目行**：取属于该编码的所有分录 `借方 − 贷方` 之和 | 被本编码标记的现金流量表分录的净额 |
| `type_subtotal` | **分类小计行**：取某一大类（经营/投资/筹资）下全部明细的净额 | 该"现金流量类型"下所有分录 `借方 − 贷方` 之和 |
| `last_period_balance` | **期初现金余额**：取所有现金/银行科目的期初余额 | 现金类科目的期初 `借方 − 贷方` |
| `above_subtotal` | **时点余额行**：取截止当前的累计余额 | 当前已累加的运行余额（above_subtotal） |

范例（安装自带）的对应关系（按"报表顺序"排列）：

```
 1~ 6  经营活动明细（公式为空，含流入/流出）
 7     经营活动产生的现金流量净额      公式=type_subtotal
 8~12  投资活动明细
13     投资活动产生的现金流量净额      公式=type_subtotal
14~18  筹资活动明细
19     筹资活动产生的现金流量净额      公式=type_subtotal
20     四、现金净增加额                公式=above_subtotal   ← 此时尚未加期初
21     加：期初现金余额                公式=last_period_balance
22     五、期末现金余额                公式=above_subtotal   ← 期初+净增加
```


### 2.3 是否流出（is_outflow）与显示符号

- `是否流出 = 0`（流入）：该行的"本月金额"直接等于 `借方 − 贷方`（正数为流入）。
- `是否流出 = 1`（流出）：保存时系统会**把金额取反**显示为正值（符合"现金流出小计"用正数表示的阅读习惯）。

> 关键点：**运行余额始终用真实的 `借方 − 贷方` 符号累加**（流出天然为负、流入为正），所以期末余额天然正确；"是否流出"只是把"流出小计"这一行的展示值翻成正。不要把"是否流出"误当成加减号开关来配。

### 2.4 现金流量类型（cash_flow_type）—— 五大归类

现金流编码的归类字段，取值为：

- `一、经营活动产生的现金流量:`
- `二、投资活动产生的现金流量:`
- `三、筹资活动产生的现金流量:`
- `四、现金净增加额`
- `五、期末现金余额`

明细行归到"一/二/三"，其 `type_subtotal` 行就会汇总对应大类。`四 / 五` 仅用于累计余额类的占位行（通常"现金流量项目名称"留空，只显示大类标题）。

### 2.5 报表顺序（report_sequence）

报表严格按照"报表顺序"从小到大排列与计算。**顺序错了，期初/期末/净增加额都会错位**。范例里 `20（净增加额）` 在 `21（期初）` 之前、`22（期末）` 在最后，这个顺序不能乱。

### 2.6 默认往来单位类型（party_type）

现金流编码上可填"默认往来单位类型"（客户 Customer / 供应商 Supplier / 股东 Shareholder / 员工 Employee）。当一笔分录的"对方"是某类往来单位、且自身没设更具体的编码时，系统会用该类型对应的默认编码兜底（见 3.3 自动取码优先级）。范例里 `1`（销售商品收款）默认客户、`3`（采购付款）默认供应商、`4`（职工薪酬）默认员工。

## 3. 自动取码优先级（重要，决定要不要手动补码）

点「获取现金流量明细」拉取明细后，系统会尽量自动给每一笔分录猜一个现金流编码，优先级如下：


1. **科目自身的编码**（`现金流量表分录.账户`，即现金/银行科目本尊，一般不用）或 **对方科目（against）的编码**；
2. **往来单位自身的编码**（现金流量表分录里的"往来单位"，仅客户 / 供应商生效）；
3. **往来单位类型的默认编码**（现金流编码上设了"默认往来单位类型"的那条）。

> 实用建议：在**对方科目**（如"主营业务收入""应交税费""应付账款"）或 **客户 / 供应商主数据** 上预先维护现金流编码，再在收付款凭证常用的"默认往来单位类型"上设默认编码。这样绝大多数分录能在拉取时一次自动归好，只剩少量特殊分录需要手填。

### 3.1 选码时的双向过滤

表单脚本在给明细选现金流编码时会自动过滤：

- 只显示"公式"**为空**（明细项目行）的编码——不能把"小计/余额"类编码选到明细上；
- 只显示"是否流出"与分录方向一致的编码——**借方（流入）只能选 `是否流出=0`，贷方（流出）只能选 `是否流出=1`**。


### 3.2 批量复制编码

在明细网格里**多选**若干行，给其中一行设好现金流编码后，系统会把同一个编码自动套到其它"尚未设码"的选中行上（方便同类分录一次性归并）。

### 3.3 一笔分录拆多类（手动拆分 manual_split）

若同一笔总账分录需要分到多个项目编码（例如一笔付款同时含货款和税费），可把该行"手动拆分"勾上——此时该行的"借方 / 贷方"变为可编辑，你把它拆成多条现金流量表分录（各自带部分金额、不同的现金流编码）。系统会校验拆分后各行的 `借方 − 贷方` 之和必须等于原总账分录的金额，否则保存报错。

## 4. 月度与"本年累计"逻辑（务必了解）

- **本月金额**：明细行 / 小计行 = 当月该编码（或该大类）的 `借方 − 贷方` 净额；期初余额 / 累计余额这两类为**时点值**。
- **本年累计金额**：
  - 普通明细行、`type_subtotal` 行、累计余额行（净增加额，此时"期初是否已计入"尚未为真）：`= 上一月已提交单据的同编码本年累计 + 本月本月金额`，逐月滚动累加。
  - 期初余额与期末余额这两类**时点行**：本年累计直接等于本月本月金额（它本身就是年初/期末的存量，不累加）。

> **关键约束**：本年累计依赖"**上一月已提交**"的现金流量表来取数。如果 2 月表在 1 月表**未提交**时就生成，"本年累计"会漏掉 1 月（只含当月）。请保证每个月**按顺序提交**。

取数范围：明细只来自 `账户类型 in ('Cash','Bank')` 且未取消的总账分录；期初余额通过 `get_rootwise_opening_balances(..., "Balance Sheet", 1)` 取得（`忽略期初` 提升性能）。

## 5. 操作流程（首次使用）

1. **（一次性）维护现金流编码**：app 安装后已自动加载范例（经营/投资/筹资/净增加额/期末余额共 22 行）。核对"报表顺序"、"现金流量类型"、"公式"、"是否流出"是否符合本企业科目结构；如有新增项目自行加行。
2. **（推荐）在对方科目 / 往来单位上设现金流编码**，或在现金流编码上设"默认往来单位类型"，减少后续手填。
3. **新建现金流量表**：填"公司"、"会计年度"、"月"（新建时系统默认带出当前会计年度与当月）。
4. **点「获取现金流量明细」**：系统把当月现金/银行总账分录拉进明细，并按 3 的优先级自动推定现金流编码。
   - 重新点会从总账**重新拉取**并清空旧明细，但会保留已有编码（通过已编码映射复用），不会丢失你手填的归类。
5. **检查/补录编码**：筛查仍为空或归错的行，逐行指定；同类可多选批量复制（3.2）；需要拆分的用"手动拆分"（3.3）。
6. **保存**：触发校验 → 自动生成现金流量表小计（本月金额 / 本年累计金额），并校验拆分金额。
7. **提交**：单据可提交，提交后该月定稿，并作为下一月"本年累计"的上游。
8. **导出**：点「下载现金流量表」把现金流量表小计导出为 CSV。

## 6. 期初 / 期末余额公式陷阱

- **`四、现金净增加额`** 用累计余额公式，但它排在"期初（21）"**之前**，所以那一刻的运行余额只含三类活动的净额、尚未加期初——其值正好是"净增加额"。**千万不要把 20 和 21 的顺序对调**，否则净增加额会被错误地包含期初。
- **`五、期末现金余额`** 同样用累计余额公式，排在最后，此时已累加期初，等于 `期初 + 净增加`。
- 修改任何"公式" / "报表顺序"后必须**保存并重新检查**整张表的勾稽，顺序一乱，净增加额与期末余额会整体错位。

---

## 7. 拆分校验

当同一总账分录被拆成多行（手动拆分）时，系统对每一个总账分录累加各行 `借方 − 贷方`，并与总账原分录的 `借方 − 贷方` 比对；差额不为 0 会直接抛错：

> `总账分录 {name} 的拆分合计 {x} 与原分录金额 {y} 不一致`

即"拆分之和必须等于原分录金额"。拆分时务必让各子行金额加总守恒。

## 8. 注意事项

1. **必须先提交上一月，本年累计才连续**：见第 4 节。
2. **重拉明细会覆盖，但保留编码**：再点「获取现金流量明细」会重新取数并清掉旧明细，已设的现金流编码通过已编码映射复用；但如果在两次拉取之间总账有新增/修改分录，旧手动归类仍会贴回对应总账分录。
3. **"公式"行不能选到明细**：明细只能选"公式"为空的编码（前端已过滤）。
4. **流入/流出方向过滤**：借方行只能选 `是否流出=0`，贷方行只能选 `是否流出=1`，选反了下拉里看不到对应编码。
5. **"是否流出"不是加减号**：它只翻转"流出小计"的展示符号，运行余额始终用真实 `借方 − 贷方` 累加（见 2.3）。
6. **命名唯一**：命名规则为 `公司_会计年度_月`，同一公司同月只能有一张；允许改名，改名后注意别造成重复。
7. **明细只含现金/银行科目**：其它科目的分录不会进入本表，属正常。

## 9. 常见错误与排查

| 现象 | 原因 | 排查/解决 |
| --- | --- | --- |
| 明细一堆行没有现金流编码 | 对方科目/往来单位未设编码、也无"默认往来单位类型" | 在对方科目或客户/供应商上设现金流编码，或补"默认往来单位类型"；再重拉或手填 |
| 下拉里找不到想要的编码 | 该编码是"公式"行（被过滤），或"是否流出"与分录方向不符 | 明细只能选公式为空且方向匹配的编码 |
| 保存报错 "总账分录 X 的拆分合计 ... 不一致" | "手动拆分"拆分各行金额之和 ≠ 原分录 | 调整拆分行的"借方/贷方"使其加总守恒 |
| 本年累计漏了上月 | 上一月现金流量表未提交 | 按顺序把上一月提交后再看本月 |
| 净增加额数值异常大/含期初 | `20`(净增加额) 与 `21`(期初) 的"报表顺序"被改 | 恢复顺序：净增加额在前、期初在后、期末最后 |
| 期末现金余额与银行账面不符 | 期初取数口径或现金类科目有遗漏 | 核对现金/银行科目是否都 `账户类型`=Cash/Bank；确认未漏未达账 |
| 某类活动净额符号相反 | `type_subtotal` 行所在大类的明细"是否流出"配错 | 检查该大类下明细的"是否流出"（流入 0 / 流出 1） |
| 重拉后手填的归类丢失 | 该总账分录不在本次重拉范围内（如被取消/改期） | 重拉后复查空编码行，重新指定 |
| 看不到「获取现金流量明细」按钮 | 未填齐"公司 & 会计年度 & 月" | 先填这三个必填项 |

## 10. 字段速查表

**现金流量表（主表）**：公司、会计年度、月、明细（现金流量表分录子表）、现金流量表小计（只读子表）、修订自。单据可提交。

**现金流编码（行模板）**：编码 code（唯一，主键）、现金流量项目名称、现金流量类型、公式（空 / `type_subtotal` / `last_period_balance` / `above_subtotal`）、是否流出、报表顺序、默认往来单位类型（客户/供应商/股东/员工，可空）。

**现金流量表分录（明细）**：账户、对方科目、往来单位类型、往来单位、借方、贷方、手动拆分、现金流编码、总账分录、凭证类型、凭证号、成本中心、项目、用户备注。借方/贷方在"手动拆分=0"时只读。

**现金流量表小计（汇总，只读）**：编码、现金流量项目名称、现金流量类型、本月金额、本年累计金额。

公式取值：空（明细行）、`type_subtotal`（分类小计）、`last_period_balance`（期初余额）、`above_subtotal`（净增加额/期末余额）。
